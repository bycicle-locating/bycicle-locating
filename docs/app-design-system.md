# App 视觉与交互规范

状态：设计基线，后续新增及修改页面必须遵循。现有页面尚未全面迁移；本文件不代表组件已实现。

## 1. 产品气质与原则

现代、安静、清晰、圆润。地图是空间背景，浮层承载操作，车辆与位置是信息主体。参考用户提供的查找类应用截图：地图全幅铺底，底部圆角面板可从摘要上拉为高版界面，导航位置稳定。借鉴信息层级与材质，不照搬设备共享等无关功能。

采用中性灰亚克力材质与克制的骑行绿。保留既有品牌色：浅色 #2E7D32、深色 #66BB6A；主按钮浅色模式白字、深色模式黑字。红色只表示危险操作或错误，不用作装饰。正文、次要文字、边线使用语义动态颜色，不在页面硬编码。

参考 Apple Design / Human Interface Guidelines 的层级、材质与无障碍方向：
- https://developer.apple.com/cn/design/
- https://developer.apple.com/design/human-interface-guidelines/materials
- https://developer.apple.com/design/human-interface-guidelines/sheets
- https://developer.apple.com/design/human-interface-guidelines/accessibility

以下数值是本项目设计起点，不是 Apple 官方参数。高斯模糊加半透明底色是本项目的亚克力实现，不宣称等同系统 Liquid Glass。

## 2. Apple 设计原则在本产品中的应用

主要参考 Apple WWDC25 **Get to know the new design system** 的官方讲解与文字稿：
https://developer.apple.com/videos/play/wwdc2025/356/

本次可以读取该视频文字稿；HIG 材质等文档网页仅返回标题，因此不将未读到的网页内容当作已核验引文。

- **内容优先**：地图、位置和车辆信息构成内容层；导航和操作浮在其上。玻璃应帮助建立层级，不能成为页面主角。阅读密集区域用更稳定、不透明的内容表面。
- **材质有职责**：Apple 将 Liquid Glass 用于独立的功能层。对应本 App，工具栏、导航和面板外壳可以使用亚克力；面板里的每一行、图标、文字不能再各自套玻璃。
- **操作分组**：相关且常用的动作靠近摆放，低频动作进入详情或更多菜单。文字按钮不硬塞进图标工具组，主动作单独突出；不为了对称添加无用按钮。
- **滚动边界**：内容滚到固定导航下方时使用轻微渐隐或分隔，表明遮挡关系。该效果只在发生遮挡处出现，同一区域不叠多重渐变，不当装饰背景。
- **同心圆角**：内外嵌套表面应共享圆心趋势。设计规则为内圆角约等于外圆角减去内间距，再按组件尺寸适配；不能把所有嵌套容器机械设成同一个大圆角。32/24/16/12 是不同角色的起点，不是嵌套时逐层强套的数值。
- **连续性**：列表进入详情尽量在同一面板中完成，保留地图空间上下文。关闭详情回到此前选择与高度，不重置地图。操作弹窗与触发它的控件建立清晰关联。
- **持久导航与上下文操作分开**：地图/骑行/车辆是稳定入口；绑定、刷新、解绑属于当前内容，不能混入主导航。面板展开也不改变标签顺序与含义。
- **克制使用品牌色**：大面积材质保持中性，绿色用于选中态和主要动作。不要把整张面板染绿，也不要照搬 Apple 的蓝色取代产品身份。

目标是遵循 Apple 的层级与交互逻辑，在 Android 上保留系统返回、键盘、安全区和无障碍习惯；不伪造系统状态栏，不将 Flutter 模糊表面称作原生 Liquid Glass。

## 3. 页面结构

### 地图首页

- 地图延伸至屏幕边缘；状态栏、交互控件及面板遵守安全区。
- 右上角仅放与地图有关的控件，统一小型材质容器，不用厚重顶部标题栏覆盖地图。
- 底部只有一个主面板，包含把手、标题、内容和固定导航。禁止再叠一张独立状态卡和第二套底栏。
- 主导航固定为地图、骑行、设置三项，各自只承担一种功能；车辆管理是从地图页进入的浮动二级页，不再占用标签，避免与地图页重复展示同一辆车。不为模仿参考图新增功能。
- 没有真实坐标就不画车辆定位点。未接地图时显示“地图暂不可用”，提示居中于未被面板遮挡的地图区域；面板升高时随可见区域上下移动并淡出，不能固定在顶部像标题，也不能被面板压住。

### 上拉面板

三档高度以安全区内可用高度 H 为参照，含固定导航区：

| 档位 | 起始目标 | 内容 |
|---|---|---|
| 收起 | 按把手、标题栏和导航实际高度计算，随字号适应 | 仅标题、添加/设置操作与底部导航，不露出被裁切的卡片 |
| 标准 | 约 50% H，默认 | 车辆列表或详情摘要、必要操作 |
| 展开 | 约 92% H | 完整详情与滚动列表 |

- 比例不是固定像素裁切：大字体、小屏和横屏优先保证可读；不足以展示摘要时合并档位，必要时使用完整页面。
- 外侧左右各留 12 logical px，底部遵守系统手势安全区；顶部圆角 32，底角 32。展开态也保留相同视觉语言。
- 把手居中，36×5，顶部留白 10；把手可见但不抢眼。标题和内容内边距 20。
- 面板内向上拖动先扩展，到最高档后内容滚动；向下滚动到顶部后才收起面板。地图手势仅作用于未被面板覆盖区域。
- 固定底栏不随内容滚走；内容底部预留底栏高度，最后一项可完全滚入可见区。
- 提供“展开/收起”可访问动作或按钮，不能只有拖拽一种操作方式。
- 主面板不可拖没；详情关闭回列表并恢复原高度。Android 返回键优先关闭弹窗、详情或收起展开态，再执行页面返回，不直接退出账号。
- 面板移动时地图可见区域随遮挡更新，选中车辆应位于未遮挡区域，不能简单放在整屏中心。
- 表单键盘出现时优先展开并保证焦点可见；关闭键盘恢复合理高度，不强制重置用户滚动位置。

### 登录、二级页与骑行

- 登录是未登录时的唯一入口：单张卡片在可用区域内水平、垂直居中，最大内容宽度 440、内边距 24；窄屏与键盘弹出时可滚动，卡片不贴顶。
- 设置、绑定与 NFC 深链是二级任务，统一使用浮动卡片：底对齐、外侧 12、最大宽度 560、最大高度 720，卡片高度随内容收缩；背景保留主面板并轻度压暗，不设全屏二级页。
- 浮动卡片有唯一标题栏（22/600）与关闭按钮；关闭回到原标签和原面板高度，Android 返回键行为一致。动效 280ms 淡入上移、220ms 退出，减少动态效果时即时切换。
- 设置与骑行复用同一表面、行高、字号、圆角；信息密集页面采用实色内容表面，不强制铺地图。
- 页面每个任务区最多一个强调主动作；解绑放独立危险操作行，不与绑定主按钮争抢视觉权重。
- 未实现功能不呈现为可操作按钮；不向用户展示 M1/M2、WebSocket、开发身份或编译参数。诊断配置仅出现在明确的开发诊断入口。
- 添加车辆只有一个全局入口：面板标题栏的“+”。地图与车辆页不再重复放置“绑定设备”大按钮；骑行页不显示“+”，避免暗示可添加骑行。
- 空状态只说明事实与下一步，不重复页面标题；不得把“尚未接入”描述为功能故障。

## 4. 设计令牌

单位均为 Flutter logical px，字号使用可缩放的逻辑字号。

| 类别 | 令牌 |
|---|---|
| 间距 | 4 / 8 / 12 / 16 / 20 / 24 / 32；禁止每页自创相近数值 |
| 页面内边距 | 20；紧凑列表可用 16，但同一页面保持一致 |
| 圆角 | 输入框 12；按钮 16；内容分组/动作卡 24；主面板 32；圆形按钮使用完整圆形 |
| 字号 | 大标题 28/34（字号/行高）；面板标题 22/28；正文和行标题 17/24；次要信息 15/21；辅助信息 13/18 |
| 字重 | 标题 600；正文 400；操作 500–600；避免全页粗体 |
| 图标 | 行图标 22–24；工具按钮图标 24；同类图标统一描边和视觉重量 |
| 可点击区域 | 至少 48×48；主按钮高 52，允许随文字放大增高 |
| 列表 | 单行最小高 56；双行最小高 72，随内容自然增高 |
| 导航 | 内容区最小高 60，另加底部安全区；图标与短标签并存 |
| 边线 | 1 个物理像素，低对比语义分隔色 |

默认系统字体，不绑定第三方字体。中文不全局强加字距；数字可用等宽数字样式避免状态跳动。允许动态字体缩放，禁止通过固定高度、禁用缩放或缩小字体解决溢出。长设备编号可换行或提供完整详情，不截断关键核对信息。

## 5. 材质配方

只有悬浮于地图/内容之上的主面板、地图工具组、导航表面使用背景模糊。内容分组使用不额外模糊的填色，从而避免“玻璃套玻璃”。

| 语义 | 浅色起点 | 深色起点 |
|---|---|---|
| 页面背景 | #F2F3F5 实色 | #111416 实色 |
| 主面板 tint | #F7F8FA，alpha 0.88 | #252A30，alpha 0.90 |
| 内部分组 | #FFFFFF，alpha 0.70 | #FFFFFF，alpha 0.08 |
| 材质高光边线 | 白色 alpha 0.45 | 白色 alpha 0.08 |
| 主面板模糊 | sigmaX/Y = 24 | sigmaX/Y = 24 |
| 阴影 | 黑色 alpha 0.10，偏移 (0,8)，blur 24 | 黑色 alpha 0.20，偏移 (0,8)，blur 24 |

参数集中管理；以真实地图明暗、道路和文字背景实测后全局调节，不允许单页私自降低 opacity。若文字受背景干扰，先提高底色遮盖，不靠加重阴影补救。禁用彩虹渐变、强发光、镜面描边、连续漂浮动画和装饰性噪点。

普通文本目标对比度至少 4.5:1，大字至少 3:1，关键控件边界/图标至少 3:1；对半透明表面必须检查合成后的最差背景，不能仅检查 tint 色。支持减少透明度时替换为对应实色表面，高对比模式加强语义文字和分隔线。以上色值是待实测的基线，不是已通过对比度认证的声明。

## 6. 组件与工程约束

现有 `app/lib/core/theme/app_theme.dart` 是主题入口。实施时在 `core/theme/` 集中间距、圆角、字号和材质令牌，在 `core/widgets/` 放跨功能共享组件。只在出现实际使用者时创建组件，不先搭通用 UI 框架。

必须统一的组件职责：
- `AppSurface`：实色/亚克力两种表面、边线、圆角与降级；模糊裁剪范围受控。
- `AppBottomSheet`：档位、拖拽与滚动协调、安全区、键盘及无障碍操作。
- `FloatingPage`：二级任务的浮动卡片、标题栏、关闭与键盘避让。
- `AppField`：文本输入的唯一形状来源（12 圆角、系统填充色、16/14 内边距）；页面不得自行拼 CupertinoTextField 样式。
- `AppActionButton`：主/次/危险语义、加载、禁用及统一点击区域。
- `AppListRow` / 分组容器：标题、次级内容、图标、尾部信息和点击反馈。
- 页面状态组件：加载、空状态、错误重试；禁止加载失败显示成空列表。

这些名称是计划中的复用边界，不表示已有实现。优先组合 Flutter/Cupertino 标准能力；页面只选语义与内容，不复制材质配方。共享组件不直接发网络请求，业务仍由 feature data/provider 管理。

禁止新增页面专属的品牌色、相近圆角或按钮样式。确有新场景，先补本规范和共享令牌，再实现调用方。改共享令牌必须回归所有使用页面。

## 7. 状态与文案

- 位置同时呈现更新时间；“最后位置”不等同“实时位置”，“无位置”不等同“离线”。
- 未绑定、加载中、网络错误、无定位、设备离线、绑定成功分别建模，不用一段默认文案覆盖。
- 没有电量、信号数据时不显示虚构零值；不把“未实现”伪装为正常空数据。
- 文案只帮助识别、选择、操作、恢复。标签用“登录”“绑定车辆”“刷新”等短语，不附技术原理段落。
- 绑定成功只说明服务端已绑定；在设备确认链路未实现前，不承诺“设备下次联网即收到指令”。
- 解绑保留后果说明与二次确认；忙碌期间防止重复操作，错误不清除表单输入。

## 8. 动效与性能

按压反馈约 120ms，页面/内容切换约 220ms，面板吸附约 300ms，使用轻微阻尼的自然过渡。拖拽实时跟手，取消夸张回弹。系统减少动态效果时取消位移与缩放，保留即时状态或短淡入。

模糊必须先裁剪再过滤；不在每个列表项上使用 BackdropFilter，不让同一区域叠加多层大面积模糊。滚动时不反复重建地图，避免全屏离屏渲染。以目标 Android/iOS 设备测量帧耗时；模糊导致明显掉帧时，统一降级为更不透明的填色，不能牺牲文字可读性。

## 9. 每次前端改动的验收门槛

1. 开工先阅读本规范和现有共享组件，说明复用哪些组件；不边写业务边临时发明风格。
2. 同一设备检查浅色/深色、三个面板档位、无数据/正常/错误/加载状态。
3. 检查约 360 logical px 窄屏、横屏、键盘弹出和 200% 字体；标题、按钮、危险操作不裁切。
4. 使用屏幕阅读器检查名称、角色、焦点顺序；面板可不靠拖动展开，状态不只依靠颜色。
5. 实际运行截图核对：边距、圆角、图标、导航、材质是否一致。仅通过 widget 测试不等于视觉验收。
6. PR 列出改动页面与共享组件，附相同尺寸的明暗截图及面板摘要/展开截图；标明未验证的设备和性能项。

首轮落地顺序：令牌与表面/按钮 → 首页可展开面板与导航 → 车辆列表/详情 → 登录与设置 → 骑行状态。统一替换旧组件，避免长期同时保留两套外观。此规范提交本身不重写业务页、不新增地图 SDK，也不改变权限边界。

## 交互全过程布局约束

已阅读 Apple Layout 官方正文（https://developer.apple.com/design/human-interface-guidelines/layout，官方 DocC 数据 https://developer.apple.com/tutorials/data/design/human-interface-guidelines/layout.json）。采用其明确原则：按重要性排序、对齐表达关联、分组与渐进披露、区分控制与内容、按实际可用空间而不是设备名称决定布局、适应字号与安全区。

- 拖拽中及吸附后：外侧边距、圆角、导航位置保持不变；仅面板高度和内容可视区变化。内容允许滚动，不得溢出面板或覆盖导航。
- 标签切换：保持当前面板高度，只有当前标签绑定面板滚动控制器，隐藏分支不得干扰拖动。
- 横屏、窄屏、大字：使用实际约束决定展开高度；正文换行，行容器增高，横向标题与附加信息空间不足时改为纵向排列。禁止全局缩小字号或关闭字体缩放。
- 键盘：表单滚动区域随 viewInsets 缩小，焦点与提交按钮必须可滚动到达，不将按钮固定压在键盘下。
- 加载、错误和成功切换：保留页面标题、左右对齐线和导航；状态区域使用统一组件，不因状态改变另起布局体系。
- 返回与弹窗：保留前页上下文，确认弹窗文字可换行；关闭后恢复可操作页面。
- 自动检查涵盖面板拖动、标签切换、窄屏/横屏/大字体布局；真实设备截图与性能检查仍单独记录，不宣称测试覆盖所有可能的交互。

### 已实现的布局约束

主面板三个标签共用固定标题栏：字号 22、字重 600、行高 1.25、左右内边距 20；收起与展开使用同一标题实例，不以阈值切换不同字号的标题。拖动只改变内容可视高度，导航固定；吸附时长统一 300ms。登录/注册表单按可用空间居中，最大内容宽度 440，窄屏与键盘下可滚动；标题、标签和输入框共用对齐线。上述数值为项目选择。

## 10. iOS 导向的交互审计（2026-11-13）

依据 Apple Designing for iOS 与 Layout：突出主要任务、减少同屏控件、让主要操作易触达、适应字号/方向/深色、保留可发现的次要操作。

已处理：
- 全屏二级页：绑定、设置、NFC 深链统一改为浮动卡片，保留背景上下文与固定关闭入口。
- 重复入口：绑定曾同时出现在标题栏“+”、地图页按钮、车辆页按钮；现只保留标题栏“+”。骑行页与设置页不显示“+”。
- 标签重复：原“地图”和“车辆”标签都在展示同一辆车；现标签为地图/骑行/设置，“车辆管理”改为从地图页车辆卡片进入的浮动页。
