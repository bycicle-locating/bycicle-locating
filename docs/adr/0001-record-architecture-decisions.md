# ADR-0001：记录架构决策

## 状态

已采纳（2026-10-30）

## 背景

本仓库跨三种语言（Dart / Go / C）与两类物理链路（LTE、BLE），
很多决定（协议单位、绑定权限归属、告警判定位置）一旦写进代码就很难回头，
而它们的影响在几个月后才会显现。仅靠 commit 历史和 PR 讨论无法追溯「当时为什么这么定」。

## 决策

采用轻量 ADR（Architecture Decision Record）：

- 位置 `docs/adr/`，命名 `NNNN-<短横线主题>.md`，四位递增序号。
- 结构固定为五节：**状态 / 背景 / 决策 / 后果 / 替代方案**。
- 状态取值：`提议中` / `已采纳` / `已废弃（被 ADR-XXXX 取代）`。
- **不改写已采纳的 ADR**。要改就新写一条并标注取代关系，历史判断本身是资产。

## 后果

- 每个 PR 若引入"难以回退"的选择（协议语义、安全边界、数据模型、硬件选型），必须附 ADR。
- 新人可以先读 ADR 建立上下文，再读代码。
- 代价：多写文档；因此 ADR 只用于真正的决策，不用于记录常规实现细节。

## 替代方案

- **只写 commit message**：跨端决策散落在多仓提交里，无法集中检索。
- **维基/外部文档**：与代码不同步，且 PR 评审时看不到。
