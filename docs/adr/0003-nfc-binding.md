# ADR-0003：用 NFC 触碰完成绑定，BLE 只做近场状态

## 状态

已采纳（2026-10-30）

> 标签物料的结论（NTAG215）已被 [ADR-0004](0004-st25dv16k-tag.md) 取代为 ST25DV16K。
> 本文件关于**绑定流程与权限边界**的决策仍然有效。
>
> 阅读提示：下文提到"标签只读 / 上锁 / 无法改写"的地方，描述的是 NTAG215 时代的**前提**；
> 换成 ST25DV16K 后标签可被设备经 I²C 改写，这些推论的理由已不成立（结论仍保留，原因见 ADR-0004）。

## 背景

需要一个"用户证明自己就在车旁边"的绑定动作。候选手段：

1. BLE 配对（输入 PIN 或 Just Works）。
2. 扫码（外壳印 QR）。
3. NFC 触碰硬件上的标签。
4. 纯账号绑定（输入设备 ID）。

同时希望 App 能显示"手机是否在车旁"，用于「找我的车」。

核心难点在于**授权边界**：谁能把这辆车绑定到自己的账号。

## 决策

**NFC 标签承担绑定入口，BLE 承担近场状态，二者的权限严格不对称。**

1. 外壳贴 **NTAG215**，写入 NDEF URI：`https://<domain>/bind?d=<deviceId>&c=<claimCode>`，随后永久上锁。
2. 手机触碰 → App 读取 `d`/`c` → 调后端 `POST /v1/devices:bind`。
3. **后端**用带 pepper 的 HMAC-SHA256 校验 `claimCode`，成功后在同一语句里写入车主，`claimed_at` 即"已使用"标记——该声明码在绑定期间失效，解绑后恢复（见 pairing.md §3）。
4. 绑定后设备经 MQTT 收 `cmd=bind` 落库，转 `CLAIMED`。
5. BLE 只提供 `device-info` / `status-notify` / `local-cmd`（闪灯、蜂鸣、立即定位），**没有任何绑定或解绑能力**。
6. BLE RSSI 只用于 UI 显示"车在附近"，带滞回与去抖，**不写后端、不作布防判据**。
7. 解绑只能由车主账号调用 `DELETE /v1/devices/{id}/binding`；物理长按只清本地缓存。

## 后果

**得到的**：

- 绑定动作物理上必须在车旁，不需要 GPS 精度也不需要摄像头。
- 绑定权在后端，与物理通道解耦；将来换二维码、换 BLE 也只需改一处接口。
- 声明码在设备已绑定期间失效，绑定期内的标签泄露因此失去价值；**解绑后原码恢复可用**，
  这是为二手转让留的出口（轮换落地前，新车主只能靠原标签绑定）。
  代价是"解绑后 → 新车主绑定前"存在抢绑窗口，由"解绑只能由车主发起"来限制。
- BLE 不参与授权，因此 BLE 协议被逆向也拿不到车。

**要接受的代价与风险**：

- **普通 NTAG 可被读取和克隆。** 若有人在车主绑定**之前**拍下/克隆标签，就能抢先绑定。
  缓解：声明码在设备已绑定期间无效，且服务端先校验声明码再判断绑定状态；
  产线包装内附封条，拆封即应尽快绑定。
  升级路径：换 **NTAG 424 DNA**（SDM/SUN 动态签名）或改用"设备屏幕/动画显示一次性码"。
  当前阶段选普通 NTAG 是因为成本与产线复杂度，**若销量上来需重新评估**。
- iOS 的后台标签读取只认 NDEF URI 记录，且需解锁；用 URI 形式正是为此。
- NFC 与 BLE 两套原生插件要分别做 Android/iOS 权限适配（Android 12+ `BLUETOOTH_SCAN/CONNECT`、
  iOS `NSBluetoothAlwaysUsageDescription`），CI 无法覆盖，需真机回归。
- 「车在附近」只是 UI 提示，用户可能误以为它等于安全状态；App 文案必须避免暗示"手机在旁即安全"。

## 替代方案

- **BLE 配对绑定（Just Works / 固定 PIN）**：任何靠近的人都能连，无法区分车主；若用随机 PIN，
  设备又无处显示 PIN（无屏幕）。排除。
- **外壳印 QR 扫码绑定**：可行且更便宜，但需要用户主动找码；NFC 是"贴上即走"的体验优势。
  保留为 NFC 失效时的降级路径（标签 URI 同时可被相机识别为普通二维码的文本除外，需另印二维码）。
- **纯账号绑定（输入设备 ID）**：等于把车送人——任何人都能输入别人的设备 ID。排除。
- **让 BLE 也参与绑定**：会让"靠近即可绑定"与"按下即解绑"这类攻击重新成立，权限边界模糊。排除。
- **声明码严格一次性（首次绑定后永久失效）**：安全语义更干净，克隆标签彻底没有价值。但 NFC 标签上锁后
  无法改写，新车主就没有任何凭证可用，必须额外引入"原车主生成一次性转让码"的流程或更换标签，
  否则二手转让完全走不通。当前阶段选"解绑后恢复可用"，用"解绑只能由车主发起"限制抢绑窗口；
  若二手交易成为主要场景，再补转让流程并把语义收紧——届时应新开一条 ADR，而不是改本文件。
