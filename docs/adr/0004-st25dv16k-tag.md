# ADR-0004：选用 ST25DV16K 作为车载 NFC 标签

## 状态

已采纳（2026-10-30）。**取代 ADR-0003 中"标签物料"部分的结论（NTAG215）**；
ADR-0003 的绑定流程与权限边界（NFC 只提供在场证明、绑定由后端核验、解绑只能车主发起）不变。

## 背景

ADR-0003 选的是 NTAG215（ISO 14443-A / Type 2 只读贴纸）。它的硬伤是**标签不可改写**：

- 声明码无法轮换，于是"解绑后原码恢复可用"成了唯一可行的二手转让路径；
- 克隆标签在"解绑 → 新车主绑定前"这个窗口内仍然有用；
- 想收紧成"严格一次性"，就只能另做转让码流程或换标签。

已采购 **ST25DV16K**：16 Kbit EEPROM，I²C 1 MHz 与 ISO/IEC 15693（NFC Forum Type 5）双接口，
内部调谐电容 28.5 pF，带 256 字节 Mailbox 与 GPO 中断引脚。

## 决策

1. 标签用 **ST25DV16K**，天线自绘（13.56 MHz 线圈）。
2. **v1 仍用静态 NDEF URI**（`https://<domain>/bind?d=<deviceId>&c=<claimCode>`），手机触碰即可绑定。
   **不使用 Mailbox 做动态挑战**：iOS 上访问 block/Mailbox 必须由 App 打开 Core NFC 会话，
   会丢掉"贴一下就走"，收益不抵损失。
3. 设备经 I²C **可以改写标签**，因此**声明码轮换**成为可能。轮换排到 M3，
   但它是本 ADR 的主要理由：轮换后旧码立即失效，克隆标签彻底没有价值，
   "解绑后恢复可用"这条妥协也就不再必要。
4. **轮换必须由后端发起**。后端只存带 pepper 的 HMAC，设备无法算出同一个哈希，
   所以不能让设备自己生成新码并上报。流程是两阶段的：
   后端生成新码并保存新哈希 → `cmd: write_claim` 下发 → 设备写 NDEF → `cmd/ack` →
   后端切换生效哈希。写失败或 ack 丢失时要保留旧码宽限期（见 protocol.md §7.3）。
5. 射频供电：ST25DV 的 RF 接口由场的能量供电，**车没电也能触碰读取**，绑定不受电池状态影响。
6. 暂不启用标签的 I²C 写保护密码（M4 评估），避免过早引入密钥管理。

## 后果

**得到的**

- 存在关闭克隆窗口的路径，且不需要转让码或更换标签；
- 设备能感知"有人正在触碰标签"（GPO 的 RF 场中断），可做诊断与唤醒；
- 2 KB EEPROM 有富余，将来可在标签里放只读的车型/序列号信息。

**付出的**

- 需要设计并调谐 13.56 MHz 天线；整机装配（金属车架、电池）会让线圈失谐，
  必须在最终结构下实测读距，必要时加隔磁片；
- 新增 I²C 接线（与 MPU-6050 共用总线，从地址 0x53 vs 0x68 不冲突）与 GPO 中断线；
- **射频与 I²C 同时访问会冲突**：写入必须避开手机正在读的时刻，靠 GPO 的 RF 场标志判断；
- NFC Forum Type 5 在 iOS 的后台触碰资料明显少于 Type 2，必须真机验证"锁屏贴一下"；
- 成本与贴片工序高于贴纸标签。

## 替代方案

- **NTAG215**：只读，无法轮换，解绑窗口无法关闭。
- **NTAG 424 DNA**：片上 AES + 每次触碰生成 CMAC 动态密文，安全性最好且仍是贴纸；
  但需要后端改造 SDM URL 的密钥与验签，且已采购 ST25DV。
- **ST25DV + Mailbox 动态挑战**：安全性接近 424，但 iOS 必须开 App，牺牲核心体验。
